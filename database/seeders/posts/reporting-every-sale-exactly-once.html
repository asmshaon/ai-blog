For almost two years I led a small team building a point-of-sale, delivery and inventory platform for licensed, regulated retailers in the US. It was multi-tenant: each retailer had its own stores, staff, settings and customers. It covered the till, delivery drivers, in-store pickup, online orders, purchasing from brands, and inventory.

One requirement shaped more of the design than any other. In this industry, every regulated sale must be reported to the state's track-and-trace system. Not most sales. Not eventually. Each one, once, and only for the items the state actually tracks.

What "exactly once" really means

"Report each sale" sounds like one API call. In practice it hides several rules:

  • Once. Reporting a sale twice overstates what left the shelf. Missing one understates it. Both show up as discrepancies an auditor will ask about.
  • Only tracked items. A store sells tracked packages and ordinary goods in the same basket. Only the tracked ones are reported.
  • Only when allowed. Sales outside the retailer's business hours, or during hours the state restricts, must not happen at all for tracked items.
  • From every channel. A sale can come from the till, a driver's delivery, a pickup order or the online store.

Report when the order completes, from one place

Because orders came from four channels, the first decision was to have exactly one order engine and exactly one place where "this order is complete" happens. Reporting hangs off that moment, not off any particular screen.

final class CompleteOrder
{
    public function __invoke(Order $order): void
    {
        DB::transaction(function () use ($order) {
            $order->markCompleted();

            $tracked = $order->lines->filter(fn ($line) => $line->product->isTracked());

            if ($tracked->isNotEmpty()) {
                ComplianceReport::firstOrCreate(
                    ['order_id' => $order->id],          // one report per order
                    ['status' => ComplianceReport::PENDING],
                );
            }
        });

        ReportSaleToState::dispatch($order->id)->afterCommit();
    }
}

Three details make the "once" hold:

  • The report row is created inside the same transaction as the order completion, with a unique key on the order. Completing an order twice can't create two reports.
  • The job is dispatched after commit, so a rolled-back order is never reported.
  • The job checks the report's status before calling the state and records the state's reference afterwards. A retried job sees "already reported" and stops.

Block what isn't allowed, before it's sold

It's much easier to prevent a sale than to explain one. The order engine refuses tracked items outside the retailer's business hours and during restricted hours, and lets untracked goods through. The cashier sees a clear message at the till instead of finding out from a compliance report a week later.

if ($line->product->isTracked() && ! $store->canSellTrackedItemsAt(now($store->timezone))) {
    throw OrderRejected::outsideSellingHours($line->product);
}

Note the store's timezone. A platform serving retailers in several states has to be careful that "10 PM" means 10 PM where the store is, not where the server is.

Keep inventory honest in both directions

Reporting sales is half the picture. Stock also arrives: stores order from brands, shipments arrive in bags on scheduled dates, and they're received against the purchase order. The platform syncs packages from the state system, reconciles quantities, records variances, and links each package to the product profile the store sells. When the numbers disagree, the system shows it, instead of silently trusting one side.

The rest of the platform

The same order engine handled discounts per item and per order, promo codes, tax-inclusive pricing and delivery fees. It also handled the driver flow: take the order, pick up, get paid, deliver with a signature. Regulation required ID checks, so the in-store queue and customer records support scanning IDs and driver licences.

Later the business spun off a wholesale product from the same code: a point of sale and admin for distributors, with its own subdomain per distributor and state-compliant transfers. I also built the company's public product website and self-service onboarding, which had to follow each state's rules, including states without the track-and-trace system.

What I'd repeat

When a rule says "exactly once", put a unique constraint where the rule lives, dispatch side effects after commit, and make the side effect check whether it already happened. And wherever you can, stop the invalid action at the point of sale rather than reporting on it afterwards.

Testing it

The tests that mattered most were the unpleasant ones: complete the same order twice, retry the reporting job after a timeout, roll back an order after the job was queued, and sell a tracked item one minute after closing time in a store two timezones away. Each of those should produce exactly one report or a clear refusal, never a duplicate and never silence.
